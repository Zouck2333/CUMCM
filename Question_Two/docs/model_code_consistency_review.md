## 4. 已确认一致的关键细节

### 4.1 信息边界

`code/solve_question_two.py` 中相似日候选索引均严格小于目标日；月初验证对每个验证日重新预测，并只选择该验证日以前的数据；当天情景和安全储备在当天残差写入前生成；当天实际负载与实际PV只在MILP计划完成后用于结算。

额外执行了两类检查：

- 对全年所有日期、负载和PV的候选规模共检查2912次，所有入选索引均满足 `selected_day < target_day`；
- 将目标日及未来实际负载、PV大幅扰动后，目标日预测最大变化为0，月初调参结果和损失不变。

因此当前标准全年执行路径没有发现未来数据泄漏。

### 4.2 等价消元

模型中的点预测约束为：

\[
G+\widehat{PV}+D=\widehat L+C+Q,
\qquad 0\le Q\le\widehat{PV}.
\]

消去 \(Q\) 后得到：

\[
\widehat L-\widehat{PV}
\le G-C+D\le\widehat L,
\]

正是 `code/solve_question_two.py:301-306` 的实现。代码在求解后反算预测弃光量。

情景中的 \(W_s\ge0\) 同样被消去为：

\[
G-C+D+R_s\ge L_s-PV_s,
\]

对应 `code/solve_question_two.py:337-344`。这是降维，不是删除物理约束。

### 4.3 数值约束复核

对正式期334天、48096条10分钟记录重新计算得到：

| 检查项 | 最大误差或违反量 |
|---|---:|
| 点预测能量平衡 | \(1.59\times10^{-12}\) kWh |
| SOC递推 | \(1.96\times10^{-11}\) kWh |
| 实际能量平衡 | \(4.55\times10^{-13}\) kWh |
| 功率上限违反量 | \(1.93\times10^{-12}\) kWh |
| 同时充放电时段数 | 0 |
| SOC实际范围 | 1200–10800 kWh |

365个每日MILP均返回最优状态，最大相对MIP间隙为 \(8.25\times10^{-7}\)，单日最长求解约0.37秒。

## 5. 与模型不一致或尚未实现的内容

### 5.1 相似日公共候选池存在歧义

`docs/model_Two.md:203-326` 字面上先定义一个公共候选集 \(\mathcal C_d\) 和一个公共距离 \(D(d,k)\)，随后分别取前 \(K_L\) 和前 \(K_{PV}\) 个日期。

代码 `code/solve_question_two.py:93-127` 把 `count` 传入候选选择，并按照“同类型日期是否达到当前 `count`”决定是否扩展到全部历史。早期日期可能出现：

- 同类型日期足够 \(K_L\)，负载只在同类型池内计算距离；
- 同类型日期不足 \(K_{PV}\)，PV在全部历史池内重新计算标准差和距离。

这样负载与PV会拥有两套候选池、标准差和距离。应明确选择一种口径：

1. 严格执行当前模型：先按 \(\max(K_L,K_{PV})\) 判断候选是否足够，构造一次公共池和公共距离，再分别Top-K；
2. 保留当前代码：把模型改写为 \(\mathcal C_d^L,\mathcal C_d^{PV}\) 及两套 \(\sigma,D\)。

为了使论文解释简洁、预测误差相关性清楚，建议采用第一种。

### 5.2 调参样本不足时没有沿用上月参数

模型规定样本不足时沿用上月参数。`code/solve_question_two.py:168-171` 在验证日不足2天时返回 `K=1, rho=1`，其中 `K=1` 不属于任何候选集合。

标准2025全年运行第一次调参发生在2月1日，当时已有14个验证日，因此该分支没有触发，不影响现有结果。但它是潜在逻辑错误，应改为将上一月 `Theta` 传入调参函数并原样返回。

### 5.3 字典序求解没有实现

模型 `docs/model_Two.md:600` 要求主费用并列时：

1. 保持主费用不超过最优值加容差；
2. 最小化 \(\sum_t(C_t+D_t)\)；
3. 固定前两层近优条件并最小化峰值购电。

当前代码 `code/solve_question_two.py:282-363` 只进行一次主费用MILP。因此主费用正确，但同价最优解中的电池吞吐量、购电峰值及具体调度轨迹可能随求解器版本变化。

### 5.4 模型承诺的对照评价缺失

以下内容目前均没有程序入口和结果文件：

- 无储备、0.75分位数、0.9分位数储备对比；
- 充放电效率均为0.9与均为 \(\sqrt{0.9}\) 的口径对比；
- 匹配约束的全年完美信息MILP；
- 取消储备并松弛互斥的完美信息LP下界；
- \(Gap_{info}\) 和 \(Gap_{LP}\)。

当前0.9储备结果仍然有效，但不能用它宣称整个模型文档已经完整实现。

### 5.5 信息边界检查还不是自动测试

虽然当前索引路径通过审查和扰动测试，`docs/model_Two.md:801-837` 的检查目前仍停留在文档伪代码。程序没有保存每日相似日、情景来源日、验证日、残差最大日期和安全储备样本最大日期，也没有在一键运行中执行未来数据扰动不变性测试。

### 5.6 指定日期结果没有完整自动生成

模型要求提取2025年3月20日、6月21日、9月23日和12月21日，按照论文表格展示逐时购电、4小时充放电、SOC和紧急购电。

## 7. 输入、输出与运行工程风险

### 7.1 输入校验不足

`code/extract_inputs.py` 当前按附件2前两个工作表的位置读取，没有按工作表名称确认；日期只核对首尾，没有检查365天连续、唯一；没有逐项核对附件1时间、附件2列标题和结果模板标题；也没有拒绝NaN/Inf。

此外，原始PV负值会被静默截成0。若负值代表测量误差，应记录修复数量；若数据应严格非负，建议直接报错，而不是无记录地修改输入。

### 7.2 4小时区间存在10分钟锚点歧义

附件和计划购电模板的数组顺序从 `0:10-0:20` 开始，第24项是 `4:00-4:10`，最后一项是 `0:00-0:10+1`。`code/build_result2.mjs` 却把前24项固定标为 `0:00-4:00`。

这与模型“每24项汇总”的索引公式一致，也与第一问现有程序口径一致，但从区间文字理解，前24项覆盖的是 `0:10-4:10`。需要根据附件时间戳究竟表示区间起点还是区间终点作最终确认，再决定是否循环移位。当前应视为高风险时间口径歧义，而不是已经证实的数值错误。

### 7.3 核验程序覆盖不完整

`code/verify_question_two.py` 已检查计划购电数组、全天合计、六段充放电汇总和Excel错误值，但没有独立核验：

- 334天日期连续且唯一；
- 144个时段标题及其顺序；
- 日初/日终SOC及跨日衔接；
- SOC递推、边界、功率和互斥；
- 紧急购电区间、区间金额和连续合并正确性；
- 计划费用与紧急购电费用；
- 相似日、场景和储备的信息边界。

因此当时的 `output/verification_report.json` 中 `PASS` 只证明工作簿若干关键数值与JSON一致，不能单独证明完整模型正确。

### 7.4 一键脚本可移植性和失败保护较弱

`run_question_two.ps1` 把当前用户缓存中的Python、Node和node_modules写成绝对路径，但求解器又调用环境变量PATH中的 `python`。换机器后不能直接运行。

同时，Windows PowerShell中 `$ErrorActionPreference="Stop"` 不一定把本机程序的非零退出码转换为异常。每一步之后没有显式检查 `$LASTEXITCODE`，某个步骤失败时可能继续使用旧JSON或旧Excel。

调试运行 `-MaxDays` 会覆盖正式JSON和CSV但保留旧的 `result2.xlsx` 与核验报告，也可能造成新旧结果混合。

## 8. 模型本身可以优化的地方

### 8.1 重新验证安全储备公式

当前公式先逐时计算：

\[
\max(0,e^L_{k,t}-e^{PV}_{k,t}),
\]

再累加。由于每项均非负，\(\max_\tau\) 实际等于全天所有正误差之和，容易把相隔很远的缺电时段全部叠加。

实际正式期结果显示：

- 平均安全储备为9477.98 kWh；
- 334天中274天达到9600 kWh上限；
- 274天的日终SOC被迫达到10800 kWh。

这说明储备规则在大部分日期失去分辨率。建议将对照公式设为：

\[
E_{k}^{need}
=
\max_{\tau}
\left[
\sum_{t=1}^{\tau}(e^L_{k,t}-e^{PV}_{k,t})
\right]_+,
\]

或者直接用历史情景下计划供需缺口计算所需电池储备，并通过严格滚动验证选择分位数和历史窗口。该修改会改变主模型结果，应作为对照模型先验证，不能静默替换当前正式方案。

NumPy当前采用线性插值分位数，模型没有定义经验分位数算法。若希望“90%样本都被覆盖”，可比较 `method="higher"` 并在文档中固定口径。

### 8.2 改进情景选择

当前情景只按工作日类型和日期新近程度选择。可比较：

- 从预测相似日或特征距离最近日中抽取联合残差；
- 使用滚动窗口避免很久以前的残差长期影响当前季节；
- 根据距离或时间衰减设置情景概率；
- 用聚类或场景缩减保留代表性联合轨迹。

这些属于模型扩展，应通过样本外费用、紧急购电量和预测覆盖率比较后再采用。

### 8.3 完善日期类型

当前周一至周五全部视为工作日，没有处理2025年法定节假日和调休。节假日日历在日前已知，不违反信息边界。加入明确日历通常能提高负载相似日质量。

### 8.4 可选实时储能对照

主模型按文档固定实际充放电计划。可另建允许实际阶段调整充放电的两阶段对照模型，比较固定计划和实时控制的费用差距。对照结果不能与当前主结果混用。
