# C题第二问模型：仅用历史数据滚动调参的日前购电与储能优化

本文件是当前程序和 `output/result2.xlsx` 对应的正式模型。默认模式为 `causal_monthly`：2月1日只用1月历史数据确定初始参数，此后每个月初仅用截至前一天的数据调参；月内固定参数，每天用新增历史数据重新拟合预测系数并更新风险余量。

## 1. 数据、时段及信息边界

附件1提供144个时段的已知电价与冷启动先验，附件2提供2025年365天的负荷和光伏实测值。功率乘以 $\Delta t=1/6$ 小时，转换为每10分钟电量kWh。检查365×144维度、连续日期、缺失值、非有限数、负值与时刻顺序，实测数据不作填补或平滑。

附件时刻是区间右端点：00:10对应0:00—0:10，0:00+1对应23:50—24:00。每24项汇总一个4小时时段。工作簿沿用题目三个工作表及列结构，时段标题按物理区间统一。

制定第d天0:00的计划时，信息集为

\[
\mathcal I_d=\{p_t,\text{已知日历},E_{d,0},L_{k,t},PV_{k,t}:k<d\}.
\]

已知星期、月底日期与剩余评价天数可以使用；当天及以后实测负荷、光伏不能用于预测、校准或调参。当天实测值在计划冻结后才进入结算。

1月是预热期：1月1日采用附件1先验，此后保留历史相似日预测，预设 $(K_L,K_{PV},\rho_L,\rho_{PV})=(4,7,1,1)$，残差情景最多14个，预热储备分位数0.90。预热策略不通过全年费用筛选。1月1日初始SOC为6000kWh，以后逐日连续。本次2月1日初始SOC为10800kWh。

正式评价期为2025-02-01至2025-12-31，共334天、48,096个时段。1月费用不计入正式总费用。

## 2. 固定调参规则与历史验证

完整正式期运行前保存 `tuning_protocol.json`，记录候选范围、评分和并列处理规则及SHA256。程序不读取旧版本的全年最优参数表，也不因全年结算费用高低而回选本次参数。

| 参数 | 候选范围 |
|---|---|
| 负荷历史窗口/天 | 14、21、28、42、56 |
| 负荷趋势阶数 | 1、2 |
| 光伏历史窗口/天 | 3、7、14、21 |
| 风险残差窗口/天 | 14、28、56 |
| 邻近时段半径/个10分钟 | 0、3、6 |
| 购电分位数 | 0.75、0.80、0.85、0.90、0.95、0.975、0.99 |
| 日末储备分位数 | 0、0.50、0.75、0.90 |

在月初d，取此前至多28天作为验证日，验证日k至少已有14天历史。2月1日的验证日期为1月15日至1月31日，其所有训练数据也都来自1月。以后月初采用同样的规则。每个候选在历史验证日k的预测只拟合k之前的数据。

选择顺序为：负荷与光伏预测参数 → 风险参数 → 储备分位数。各阶段都仅使用截至月初d之前的数据。评分先四舍五入至8位小数处理数值并列，再按预先规定的较低阶数、较短窗口、较小分位数或半径排序。

调参函数的实测数组实际被截断为 `actual_load[:d]` 与 `actual_pv[:d]`；数组长度必须恰好等于历史日期数，包含未来尾部的输入会被拒绝。

## 3. 候选预测模型

负荷逐时段使用对数负荷的局部趋势与星期效应。取最近W天，令 $\tau_k=(k-d)/28$，趋势阶数为a：

\[
x_k=(1,\tau_k,\ldots,\tau_k^a,I_{Mon}(k),\ldots,I_{Sat}(k)),
\quad y_{k,t}=\log\max(1,L_{k,t}).
\]

星期日为参考类别，六个星期系数由历史数据学习，不预设周末为低负荷日。拟合和预测为

\[
\widehat\beta_t=(X^TX+\Lambda)^{-1}X^Ty_t,
\quad \Lambda=\operatorname{diag}(10^{-8},0.01,\ldots,0.01),
\quad \widehat L_{d,t}=\exp(x_d\widehat\beta_t).
\]

光伏以最近V天逐时段拟合线性趋势，$z_k=(1,(k-d)/V)$：

\[
\widehat\gamma_t=(Z^TZ+\operatorname{diag}(10^{-8},0.3))^{-1}Z^TPV_t,
\qquad \widehat{PV}_{d,t}=\max(0,\widehat\gamma_{t,0}).
\]

重算早期历史候选时，负荷历史不足14天则使用前一周同日、或最早已完成日；光伏历史不足3天则使用前一天。1月1日历史候选使用附件1先验。

负荷和光伏分别选择历史验证中平均电价加权绝对误差最小的参数：

\[
J_{forecast}=\frac{1}{144|\mathcal V_d|}\sum_{k\in\mathcal V_d,t}p_t|\widehat y_{k,t}-y_{k,t}|.
\]

月内参数固定但回归系数每日重新拟合。JSON的全局窗口、分位数字段在本模式下为null，实际参数以 `policy_updates` 和每日CSV为准，不能把12月参数误报为全年固定值。

## 4. 风险余量与购电分位数选择

月初选出预测参数后，按该组参数重算截至前一天的历史逐日前推候选预测。对每个历史日k，回归仍只拟合k之前的实测数据。重算用于估计当前模型的误差，不会改写已经执行的历史购电或SOC。

定义当前参数下的联合净负荷残差

\[
e_{k,t}^{(\theta)}=(L_{k,t}-PV_{k,t})-(\widehat L_{k,t}^{(\theta)}-\widehat{PV}_{k,t}^{(\theta)}).
\]

对第d天t时段，合并此前W_r天全部日期、邻近r个时段的残差，排除1月1日，日界截断，不跨日环绕：

\[
b_{d,t}=\max\{0,Q_q(e_{k,u}^{(\theta)}: \max(1,d-W_r)\leq k<d,\ |u-t|\leq r)\}.
\]

这里采用从0开始的日期索引，k=0为1月1日。经验分位数采用 `inverted_cdf`，即n个样本排序后取第 $\lceil qn\rceil$ 项。时间邻域包含的是已经发生的历史日期的时段，不是当天未来时段。

正式供能下限保证实际紧急购电满足

\[
U_{d,t}^{act}\leq(e_{d,t}^{(\theta)}-b_{d,t})_+.
\]

因此，风险候选的历史紧急费用上界均值和费用代理分别为

\[
B=\frac1{|\mathcal V_d|}\sum_{k\in\mathcal V_d,t}5p_t(e_{k,t}-b_{k,t})_+,
\quad J_{risk}=\frac1{|\mathcal V_d|}\sum_{k\in\mathcal V_d,t}p_t[b_{k,t}+5(e_{k,t}-b_{k,t})_+].
\]

若正式紧急费用预算为100万元，月初可使用的历史信息给出每日预算参考

\[
\bar B_d=\frac{\max(0,10^6-\sum_{31\leq k<d}F_k^{emergency})}{\text{剩余正式日历天数}}.
\]

先在历史B不超过该参考值的候选中选最小 $J_{risk}$；若没有合格候选，则选历史B最小者，再按代理费用排序。该规则只使用已结算费用和已知日历。历史上界均值不是未来预算保证，年度金额最终仍由实际结算验收。风险代理不是带电池耦合的精确总费用目标。

## 5. 日末储备选择

对当前预测参数的历史残差，计算

\[
H_k=\sum_{t=1}^{144}(e_{k,t}^{(\theta)})_+,
\quad R_d(\alpha)=\min\{9600,Q_\alpha(H_k:k<d)/\eta_d\}.
\]

此处储备历史包含冷启动日；与风险余量的排除规则不同。分位数采用 `linear`，少于5个历史残差日或 $\alpha=0$ 时储备为0。

月初对四个储备分位数分别在最后14个历史验证日进行连续SOC的日前MILP模拟，采用已经选定的预测和风险参数，按各历史日实际数据事后结算。各候选验证起点SOC均为10800kWh，最后一个验证日强制至少回到10800kWh，避免通过消耗更多末端储电量制造费用优势。按这14天实际总费用选择储备分位数。

统一首末SOC仅用于候选比较，正式逐日计划不强制首末SOC相同。正式当天只要求 $E_{d,144}\geq1200+R_d$，SOC从前一天连续传递。

## 6. 正式日前购电—储能联合MILP

每个时段的决策为正常购电G、输入侧充电C、输出侧放电D、内部储电量E及二元充放电状态z：

\[
G_t+D_t-C_t\geq\widehat L_t-\widehat{PV}_t+b_t,\qquad G_t,C_t,D_t\geq0,
\]
\[
E_t=E_{t-1}+0.9C_t-D_t/0.9,\qquad1200\leq E_t\leq10800,
\]
\[
0\leq C_t\leq(5000/6)z_t,\quad0\leq D_t\leq(5000/6)(1-z_t),\quad z_t\in\{0,1\}.
\]

点预测富余 $W_t=G_t+\widehat{PV}_t+D_t-\widehat L_t-C_t\geq b_t$ 表示总供能富余或未利用的已付费购电额度，不仅是弃光，不施加 $W_t\leq\widehat{PV}_t$。全部G照常付费，富余不出售、不退款、不额外改变SOC。CSV中的兼容字段 `predicted_curtailment_kwh` 在本模型下表示W。

三级词典序目标依次最小化正常购电费用 $\sum_tp_tG_t$、电池吞吐量 $\sum_t(C_t+D_t)$、购电峰值 $\max_tG_t$。后一级受前一级近优锁定约束。正式期 `scenario_count=0`，风险由供能下限表示，不再叠加原情景期望紧急费用目标。

## 7. 实际结算、核验及适用范围

购电和充放电计划冻结后，实际紧急购电和费用为

\[
U_{d,t}^{act}=(L_{d,t}+C_{d,t}-PV_{d,t}-D_{d,t}-G_{d,t})_+,
\quad F_d=\sum_tp_tG_{d,t}+5\sum_tp_tU_{d,t}^{act}.
\]

实际富余为相反缺口的正部，与紧急购电互斥。当天实测仅更新结算与后续历史库。实际C、D执行已确定计划，SOC按固定充放电递推。

`verify_causal_policy.py` 不导入调参器、预测实现或MILP求解器，独立用增广最小二乘、分位数选秩、费用与SOC公式重算候选评分、储备验证调度、每日预测、风险余量和储备。`verify_question_two.py` 同时核验正式48,096个时段和JSON/CSV/Excel全量映射。

信息边界测试以2月1日和6月1日为目标，扰动当天及以后全部实测值，然后从1月重新运行，包括各月参数选择、候选评分及验证调度。比较到目标日为止的参数、评分、验证调度和当天计划，而非只在已经固定的最优参数下测试。

完美信息MILP和LP只用于事后成本参照，其结果不进入预测、选参、储备或日前计划。本程序按历史截止实施参数选择；由于候选模型的设计受到此前研究启发，本次回算仍不是从未查看过2025年数据的外部独立验证，也不保证未知年份达到相同费用。

当前数值以 `output/result_summary.md` 为准，月度截止日期与参数见 `output/policy_updates_summary.csv`。运行入口为 `run_question_two.ps1`，旧固定参数实验需显式指定 `-ParameterMode fixed`。
