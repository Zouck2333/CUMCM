# Question One 优化版程序核对报告

> 状态更新（2026-09-11）：本报告记录的是修改前发现的问题。运行环境分离、脚本退出码、默认费用目标、后验约束检查、参数校验以及灵敏度结果不同步问题现已修复。最新验证结果见 `verification_report.md`。

## 1. 核对目的

本报告对以下两个目录进行比较：

```text
Question_One
Question_One_optimized
```

核对重点包括：

1. LP 与 MILP 数学模型是否保持正确；
2. 优化版能否在当前计算机环境中直接运行；
3. 输入、输出和命令行接口是否合理；
4. 字典序优化是否符合问题一的主要目标；
5. 灵敏度分析及验证报告能否复现；
6. 优化版是否适合直接替换原程序。

本次工作只进行了代码和结果核对，没有修改求解程序。

## 2. 总体结论

`Question_One_optimized` 的升级方向合理，增加了参数化、字典序多目标优化和批量灵敏度分析，代码扩展能力明显强于原版。

但是，优化版当前在本机默认环境下不能直接运行，并且已有验证报告和灵敏度结果与当前目录中的代码、文件状态不完全对应。因此，现阶段不建议直接用优化版替换 `Question_One`。

建议保留优化版的参数化和灵敏度分析设计，修复运行环境、启动脚本、默认优化目标和结果校验后，再将其作为正式版本。

## 5. 主要问题

### 5.1 运行环境兼容性退步

问题等级：高。

原版采用主程序与求解进程分离的方式：

- 工作区 Python 负责读取 Excel、处理 DataFrame 和写入结果；
- 系统 Python 负责调用 SciPy/HiGHS 求解 LP 或 MILP。

优化版取消了这一机制，在主程序中直接执行：

```python
from solver_worker import solve as solve_worker
```

这要求同一个 Python 环境同时安装 NumPy、pandas、openpyxl 和 SciPy。当前机器不具备这样的默认环境，所以优化版无法直接运行。

建议采用以下方案之一：

1. 恢复原版的独立求解进程机制；
2. 在项目中创建并固定一个完整虚拟环境；
3. 启动脚本在运行前检查全部依赖，并给出明确安装提示。

从程序移植性考虑，优先建议恢复独立求解进程，或者提供自动创建虚拟环境的安装脚本。

### 5.2 PowerShell 脚本会掩盖 Python 运行失败

问题等级：高。

三个启动脚本均使用类似方式调用 Python：

```powershell
& $python ...
```

但没有在调用后传递 Python 的退出码，例如：

```powershell
exit $LASTEXITCODE
```

实际测试中，Python 已输出异常堆栈，但 PowerShell 脚本的退出状态仍显示为成功。这可能导致自动验证、批处理程序或使用者误以为求解已经完成。

建议所有启动脚本在 Python 命令后增加：

```powershell
if ($LASTEXITCODE -ne 0) {
    exit $LASTEXITCODE
}
```

### 5.3 默认 MILP 不再严格保持最低购电费用

问题等级：中高。

优化版对 MILP 的默认设置为字典序优化，依次执行：

1. 最小化购电费用；
2. 在近优费用范围内最小化电池吞吐量；
3. 在近优费用和吞吐量范围内最小化峰值购电功率。

费用容差定义为：

```python
cost_tol = max(1e-5, abs(cost_opt) * 1e-9)
```

根据现有验证报告，结果为：

| 指标 | 费用目标 MILP | 字典序 MILP | 变化 |
|---|---:|---:|---:|
| 购电费用/元 | 35126.948589290 | 35126.948624417 | +0.000035127 |
| 电池吞吐量/kWh | 37540.605698354 | 37540.604944304 | -0.000754050 |
| 峰值购电功率/kW | 8458.827300000 | 8458.814806002 | -0.012494 |

费用增加量很小，且在代码设置的容差内，但第一问的首要目标是尽可能节省购电费用。因此，从题意和论文表达出发，不宜默认输出费用略高的字典序解。

同时，字典序优化带来的吞吐量和峰值改善非常小，实际意义有限。

建议：

- 默认 MILP 使用纯购电费用目标；
- 将字典序优化保留为可选参数；
- 在论文扩展分析中展示字典序结果，不作为第一问正式提交结果。

### 5.5 灵敏度结果与当前代码不匹配

当前 `sensitivity_results.csv` 只有以下 8 列：

但当前 `sensitivity_analysis.py` 应生成更多字段，包括：

这说明已有 CSV 不是由当前版本代码完整生成，或者代码在生成结果后又经过了修改。现有灵敏度结果不能作为当前代码已经通过验证的充分证据。

建议修复运行环境后删除旧结果并重新执行完整灵敏度分析，再核对输出列、情景数量和约束指标。

### 5.6 输出校验项目有所减少

问题等级：中。

原版除能量平衡、SOC 递推和充放电功率检查外，还检查：

- 弃光量是否小于 0；
- 弃光量是否超过当前光伏发电量；
- 同时充放电的重叠电量。

优化版只统计同时充放电时段数，没有统计重叠电量，也删除了弃光上下界的结果校验。

虽然求解模型中仍包含弃光约束，但输出结果还会经过数值截断和 DataFrame 重建。保留独立的后验校验更稳妥。

建议恢复：

```text
curtailment_violations
simultaneous_charge_discharge_kwh
```

并增加：

```text
soc_lower_bound_violations
soc_upper_bound_violations
terminal_soc_error
```

### 5.7 参数缺少前置合法性检查

问题等级：中低。

优化版允许通过命令行修改效率、SOC 范围和功率上限，但没有在进入求解器前完整检查参数。例如：

- `eta` 应满足 `0 < eta <= 1`；
- `soc_min` 应小于 `soc_max`；
- 初始和终端 SOC 应位于允许范围内；
- 最大充放电功率应大于 0；
- 负载和光伏缩放系数不应为负数；
- `mip_gap` 和 `time_limit` 应为合法非负值。

当前错误参数可能产生除零异常、不可行模型或难以理解的求解器错误。建议在读取参数后统一进行验证，并给出中文错误提示。

## 6. 优化版的有效改进

虽然目前存在问题，优化版仍包含多项值得保留的升级。

### 6.1 模型参数化

以下参数可通过命令行调整：

- 充放电效率；
- SOC 上下限；
- 初始 SOC；
- 终端 SOC；
- 最大充放电功率；
- 负载缩放系数；
- 光伏缩放系数。

这些接口有利于开展敏感性分析，也减少了修改源代码常量的需要。

### 6.2 独立设置终端 SOC

原版固定初始 SOC 与终端 SOC 相同。优化版允许单独设置终端 SOC，在研究跨日调度或不同运行边界时更灵活。

### 6.3 字典序多目标框架

字典序优化的代码结构具有扩展价值，可用于研究：

- 购电费用；
- 电池吞吐量；
- 峰值购电功率。

该功能更适合设置为扩展模式，不宜取代问题一默认的最低费用目标。

### 6.4 批量灵敏度分析

灵敏度程序覆盖：

- 初始和终端 SOC；
- 储能效率；
- 光伏预测变化；
- 负载预测变化；
- 最大充放电功率；
- SOC 可用区间；
- 负载、光伏和效率组合情景。

这些分析有助于论文的模型评价和敏感性分析章节。

### 6.5 输出目录更加清晰

优化版将主要结果集中在 `output` 目录中，并将灵敏度结果放入子目录，文件组织比原版更清晰。

## 7. 模型正确性判断

从代码结构看，优化版的基础 LP 和 MILP 模型仍然正确。

### 7.1 LP

标准 LP 保留：

- 购电、充电、放电、弃光和 SOC 连续变量；
- 电力平衡约束；
- SOC 递推约束；
- 储能容量和功率约束；
- 初始、终端 SOC 约束；
- 弃光上限约束。

LP 不包含二进制变量及充放电互斥约束，符合上一版约定。

### 7.2 MILP

MILP 增加二进制充放电状态变量，并通过 Big-M 约束禁止同一时段同时充电和放电。其物理含义和数学表达正确。

### 7.3 峰值变量

优化版增加峰值购电功率变量，并约束其不低于每个时段的购电功率。该变量用于字典序第三阶段，建模方式正确。

因此，当前主要风险来自程序环境、默认目标设置和验证可复现性，而不是基础能量调度公式。

## 9. 建议修改顺序

建议按以下顺序修复优化版：

1. 修复 Python 环境调用，使 LP、MILP 和灵敏度分析能够在当前机器实际运行；
2. 修复三个 PowerShell 脚本的退出码传递；
3. 将 MILP 默认目标改为严格最小化购电费用；
4. 保留 `--objective-mode lexicographic` 作为扩展选项；
5. 恢复弃光、同时充放电量和 SOC 边界等后验检查；
6. 增加命令行参数合法性检查；
7. 使用当前代码重新生成 LP、MILP 和灵敏度结果；
8. 用当前实际存在的原版 CSV 重新完成逐时段比较；
9. 更新 README 和验证报告，使代码、命令、结果及路径完全一致；
10. 全部检查通过后，再决定是否替换原版目录。

## 10. 最终评价

优化版在功能设计和扩展能力方面优于原版，但当前还不是可直接交付的稳定版本。原版目前更适合作为可运行的正式求解程序，优化版更适合作为待修复的下一版本。

完成环境兼容、默认目标和验证流程修复后，优化版将更适合论文分析及后续问题扩展。
